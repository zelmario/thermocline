Thermocline is a tiering proxy for a MongoDB replica set that has outgrown
its memory. This release is the one to try it with: `cline adopt` reads the
cluster you already have and writes the configuration that tiers it.

**This is a proof of concept, not a product.** It has run against two real
replica sets in a test rig and on staging hardware with a simulated shop, not
in production. Read [docs/limitations.md](https://github.com/zelmario/thermocline/blob/v0.2.0/docs/limitations.md)
before you point anything at it, and try it on a copy of your data first.

## New: `cline adopt`

Writing `cline.yaml` by hand meant knowing, for every collection, whether it
can be tiered and what ages its documents. `cline adopt` works that out by
sampling every collection on the archive, without writing to either tier:

```
cline adopt --hot "mongodb://fast1,fast2,fast3/?replicaSet=rsFast" \
            --cold "mongodb://old1,old2,old3/?replicaSet=rsOld" \
            --fast-size 200GB
```

It writes `cline.yaml` in the current directory (`--out` to change it). Each
decision is written into the file as a comment with its evidence: the
ObjectId in `_id`, or a date field when `_id` is not an ObjectId or a migration
re-inserted the documents. Collections it will not tier are listed with the
reason, and a collection under 1 GB is kept whole on the fast tier, since
tiering it frees almost nothing. It then runs `cline preflight` on the result and prints what is left
before the cutover: accounts, archive indexes, collections to copy whole, views,
and the connection string your application should use.

On a 60 million order archive (52 GB) it took 17.6 seconds and 21 MB. On the
Docker rig it estimated 24.7% of orders kept at 180 days, and `cline run` with
the generated file held 24.8%.

## Changes

- **Counts on the archive use its indexes.** Every count the archive answered
  filtered out deleted copies with a condition no index serves. On the staging
  archive, `countDocuments` of the last 30 days took 53s through the proxy and
  0.3s on the archive directly. It is now two counts the planner can serve from
  indexes: on 1M documents, a year by `_id` went from 176ms to 52ms.
- **`estimatedDocumentCount` stays a metadata read** through the proxy.
- **A stale archive pages.** Under `router.freshness: strict`, the default, a
  read refused because mirroring was behind is counted in
  `thermocline_stale_refusals_total`, and the `ThermoclineStaleRefusal` alert
  fires on it. Before, those refusals were counted with every other refusal,
  and on a degraded staging volume 9,314 application errors in five minutes
  paged nobody.
- **Copy-ups run in a registered session**, as warms do, and wait for `w:1`
  instead of majority. That halves the hold on each copy-up.
- **`packaging/install.sh` creates `PREFIX`** when you install somewhere
  other than `/usr/local/bin` and the directory is not there yet.
- **The live cache answers more** (`router.live_cache`, off by default). It
  now also answers a `find` with no limit up to 500 documents, `_id: {$in}`,
  clients on the Stable API, and `count` and `countDocuments` on tiered
  collections. See [docs/live-cache.md](https://github.com/zelmario/thermocline/blob/v0.2.0/docs/live-cache.md).

## Requirements

- Both tiers are replica sets, on the same MongoDB release and feature
  compatibility version. `cline` refuses to start otherwise, and says why.
  Sharded clusters are not supported.
- Tested on MongoDB 7.0 and 8.0.
- Linux on amd64 or arm64. The binary is static and needs nothing else.

## Install

Download the tarball for your platform and check it:

```
curl -LO https://github.com/zelmario/thermocline/releases/download/v0.2.0/cline-0.2.0-linux-amd64.tar.gz
curl -LO https://github.com/zelmario/thermocline/releases/download/v0.2.0/SHA256SUMS
sha256sum -c SHA256SUMS --ignore-missing
```

Install it as a set of systemd services:

```
tar xzf cline-0.2.0-linux-amd64.tar.gz
cd cline-0.2.0-linux-amd64
sudo packaging/install.sh ./cline
```

Write `/etc/cline/cline.yaml` (owned by `cline`, mode 0640) with `cline adopt`
or from `cline.example.yaml`. Check the pair of tiers, which writes nothing and
refuses a pair that cannot work, then start it:

```
cline preflight --config /etc/cline/cline.yaml
sudo systemctl enable --now cline
```

For a cluster already serving traffic, follow the numbered order in
[docs/adoption.md](https://github.com/zelmario/thermocline/blob/v0.2.0/docs/adoption.md)
instead of starting everything at once.
