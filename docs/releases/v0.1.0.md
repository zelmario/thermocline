The first release of Thermocline, a tiering proxy for a MongoDB replica set
that has outgrown its memory.

**This is a proof of concept, not a product.** It has run against two real
replica sets in a test rig and on staging hardware with a simulated shop, not
in production. Read [docs/limitations.md](https://github.com/zelmario/thermocline/blob/v0.1.0/docs/limitations.md)
before you point anything at it.

## What it does

Your existing replica set becomes the archive, unchanged. A small, fast replica
set goes in front of it and fills with the documents your application uses. One
binary, `cline`, runs every component:

- **The proxy** listens where the application connects and sends each command
  to the tier that can answer it. The application keeps its queries and only
  changes the connection string.
- **The feeder** mirrors every write on the fast tier into the archive.
- **The evictor** removes documents older than their collection's age from the
  fast tier, once the archive holds them.
- **The warmer** fills the fast tier with what is newer than that age.

## Requirements

- Both tiers are replica sets, on the same MongoDB release and feature
  compatibility version. `cline` refuses to start otherwise, and says why.
  Sharded clusters are not supported.
- Tested on MongoDB 7.0 and 8.0.
- Linux on amd64 or arm64. The binary is static and needs nothing else.

## Install

Download the tarball for your platform and check it:

```
curl -LO https://github.com/zelmario/thermocline/releases/download/v0.1.0/cline-0.1.0-linux-amd64.tar.gz
curl -LO https://github.com/zelmario/thermocline/releases/download/v0.1.0/SHA256SUMS
sha256sum -c SHA256SUMS --ignore-missing
```

Install it as a set of systemd services:

```
tar xzf cline-0.1.0-linux-amd64.tar.gz
cd cline-0.1.0-linux-amd64
sudo packaging/install.sh ./cline
```

Then write `/etc/cline/cline.yaml` (owned by `cline`, mode 0640) from
`cline.example.yaml`. Check the pair of tiers, which writes nothing and refuses
a pair that cannot work, then start it:

```
cline preflight --config /etc/cline/cline.yaml
sudo systemctl enable --now cline
```

For a cluster already serving traffic, follow the numbered order in
[docs/adoption.md](https://github.com/zelmario/thermocline/blob/v0.1.0/docs/adoption.md)
instead of starting everything at once.

## Security

This release includes the fixes from a security review of the whole codebase.
Among them: guards that read the archive now check the client's privileges
first, messages nested deeper than 1,000 levels are refused, and a client has
`router.message_timeout` (default 2m) to finish a message, with
`router.max_connections` (default 20000) capping open connections.

Authentication is proxied to the fast tier by default. `router.terminate_auth`
ships off; [docs/dashboard.md](https://github.com/zelmario/thermocline/blob/v0.1.0/docs/dashboard.md)
explains what turning it on changes.
